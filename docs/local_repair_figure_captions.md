# Local Repair Figure Captions

## 1. Use

本文档提供局部修复相关图表的论文图注草稿，面向第 5 章实验部分直接复用。

## 2. Figure A

图名建议：

`Full-Replan` 与 `LocalRepair` 在扩展对比场景下的甘特图比较

图注草稿：

在 `t=45` 走廊资源 `corridor_H` 变为 `temporary_occupied` 后，完整重规划与局部修复对剩余任务的处理方式出现差异。图中给出了静态基线、完整重规划结果和局部修复结果三组任务时间安排。红色边框表示受扰动影响任务，绿色边框表示被冻结任务，虚线边框表示相对静态基线发生变化的任务。可以看到，`Full-Replan` 会调整未受直接扰动的未来任务顺序，而 `LocalRepair` 保留冻结前缀与未受影响子计划，仅对受影响子集进行重优化。

## 3. Figure B

图名建议：

扩展对比场景下的资源状态与 `supply_point_S` 占用时间线

图注草稿：

该图展示了扩展局部修复对比场景中的关键资源演化。第一行给出 `corridor_H` 的状态时间线，显示其在 `t=45` 由 `free` 变为 `temporary_occupied`，随后恢复为 `free`。其余各行给出静态基线、完整重规划和局部修复下 `supply_point_S` 的占用顺序。对比可见，完整重规划会交换 `T6` 与 `T7` 的未来执行顺序，而局部修复保留未受影响的未来任务 `T7`，只允许受影响任务集合内的调整，从而体现最小扰动特性。

## 4. Figure C

图名建议：

主最小实验中的动态重规划甘特图

图注草稿：

该图给出了冻结主场景下，规划器在空间资源扰动前后的任务安排变化。与静态基线相比，当 `corridor_H` 在 `t=45` 进入 `temporary_occupied` 状态后，规划器根据资源可用时间窗约束将 `T4` 延后，从而避免走廊冲突并保持前驱与事件区约束可行。图中变化仅发生在受资源时间窗影响的任务上，验证了动态空间状态向规划层的有效传递。
