# 2026-10-09 DUCT 三维人体可视化稳定化与新网络适配

## 任务目标

解决 RViz 人体骨架闪烁、多人重叠、文字混乱和点云造成的卡顿；适配小车新地址 `192.168.31.191`，并复核遥控器仍显示原始画面的原因。

## 实机诊断

- 工作站地址为 `192.168.31.221`，小车地址为 `192.168.31.191`。
- 小车本机 Gemini、RTAB-Map、TF 与里程计话题正常；工作站无法通过多播发现小车话题。
- 在双方 Cyclone DDS 配置中互设显式 peer 后，独立测试话题连续 11 次双机接收成功。
- 原 RViz 节点每帧先发 `DELETEALL`，空检测帧会立即清除骨架；多人检测和 Track ID 变化会制造多套文字、骨架和测距线。
- 截图中启用了 `/cloud_map`。点云跨 Wi-Fi 与 RGB、深度争用带宽，是明显卡顿来源。
- 新地址下只有小车原始 `8554` RTSP 服务运行，独立三维画面服务没有自启动，因此遥控器仍显示原画面是符合当前状态的。

## 实现变更

- 工作站 Cyclone peer 更新为 `192.168.31.191`；新增小车端 peer 配置，指向 `192.168.31.221`。
- 三维 Marker 默认只显示质量最高的一人，Track ID 默认隐藏。
- 空检测/短时通信抖动时保持最近骨架 1.2 秒，超时后才清除。
- 对中心和关节点执行 EMA 平滑，默认系数 0.45。
- RViz Marker 默认要求有效 `map` 坐标，避免在 `map/odom/base_link` 之间跳变。
- Marker 发布改为 Reliable + Transient Local，RViz 晚启动可立即取得最近状态。
- 工作站 RViz 降为 15 FPS，点云默认关闭。
- 新增小车端 RViz 配置：地图、点云在小车本机读取，仅接收轻量人体 Marker。
- 三维 RTSP 改回压缩图输入，并新增用户级服务文件；它不会替换原始 `8554/stream`。

## 验证

- ROS2 包重新编译成功。
- 合成双人输入只生成一套人体 Marker。
- 空检测后 0.6 秒 Marker 保持，1.2 秒超时后发送一次 `DELETEALL`。
- 新网络显式 peer 测试连续接收成功。
- 小车端配置已部署，旧 Cyclone 配置备份为 `/data/ductcleanrob/scripts/cyclonedds.xml.bak_20261009`。
- `pose3d-rtsp.service` 已部署为小车用户服务并启动，当前监听 `8555`；服务已启用，但 `Linger=no`，无人登录的冷启动场景仍需后续处理。

## 未解决风险

- 小车现有 ROS2 进程仍使用启动时读取的旧 DDS 配置，需要一次受控重启后才能完成全链路实机验收。
- 遥控器当前固定使用原始 RTSP 地址；新增画面不会自动替换已有画面，需要遥控器支持切换 URL/通道或修改遥控器程序。
- 小车端 RViz 可降低点云跨网开销，但不能消除电脑端推理所需的压缩 RGB、深度传输。
- 若同时在工作站和小车端开启点云显示，仍会产生无意义的重复负载。
