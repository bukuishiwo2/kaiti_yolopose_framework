### 3. AMCL 初始位姿配置

新增 `kaiti_house_localization.yaml`，在官方 TurtleBot4 localization 参数基础上加入：

```yaml
set_initial_pose: true
always_reset_initial_pose: true
initial_pose:
  x: 0.8
  y: 0.8
  z: 0.0
  yaw: 0.0
```

该配置用于避免 AMCL 未收到初始位姿时长期不发布 `map -> odom`，从而导致 RViz 固定到 `map` 报错、Nav2 costmap 等待 TF 超时。

注意：如果保存的静态地图坐标系与 Gazebo 初始位姿不一致，仍需要在 RViz 中使用 `2D Pose Estimate` 手动校准一次。

### 4. 当前运行层级结论

在线检查结果：

- `/map` 已发布，尺寸为 `229 x 241`，分辨率 `0.05 m/pix`，origin 为 `(-3.93, -4.38, 0)`。
- `configs/planner_waypoints.yaml` 中 `A/B/C/D/S` 均在该地图边界内。
- `/tf` 中可以看到 `odom -> base_link`，但必须使用仿真时间理解 TF。
- 编译前运行的旧 launch 中 `/amcl set_initial_pose=False`，因此不会稳定发布 `map -> odom`。

所以静态地图入口的问题不是 MILP 算法不可行，也不是 `/map` 完全没有发布；主要是旧安装配置和 AMCL 初始位姿导致 TF 树没有建立。当前为了保证可运动联调，应优先回到 RTAB-Map 在线建图入口。

### 5. RViz 地图显示说明

如果 `/map` 已发布但 RViz 仍不显示地图，需要检查两点：

- RViz Fixed Frame 是否为 `map`，且 `map -> odom -> base_link` 已连通。
- RViz 的 Map display 订阅 `/map` 时，Durability 应设置为 `Transient Local`，否则 RViz 后启动时可能错过 map server 的 latched map。

该问题属于显示与 TF 初始化问题，不应继续通过修改 MILP 或 executor 规避。
