# 2026-10-10 小车三维定位与遥控器续验

## 目标

恢复重启后的真实 RGB-D、TF、人体三维坐标与遥控器标注视频，保持底盘静止，不发送运动命令。

## 实机发现与修复

- SSH `duct@192.168.31.191`、有线 `192.168.144.30`、遥控器 `192.168.144.20:5555` 均可连接。
- 相机服务虽然短暂显示 active，但在循环重启：`Failed to find a free participant index for domain 8`。本机 Cyclone 默认 MaxAutoParticipantIndex=9；双方配置改为 120 后相机恢复。
- 昨日“关闭多播后带宽降低”不能单独证明多播是根因：相机启动失败也会降低流量。今日订阅图像后有线路径约 85 Mbps，改用实验室 Wi-Fi 传 DDS；遥控器有线路径保留视频。禁止多播、显式 peers，避免无意跨图传网络传大数据。
- 相机、建图和 robot-nav-start 的 systemd drop-in 明确指定 Cyclone。其他厂商服务未整体替换中间件。
- 小车比 NTP 已同步的电脑快约 377 秒，NTP 域名经代理解析为 198.18.0.6，无法同步。设置数字 NTP endpoint 仍无回包；本次通过 SSH 对齐电脑时间，并重启感知节点清除时间倒跳缓存。后测偏差约 -0.23 秒（SSH RTT 0.15 秒），尚不是精确时钟同步。
- 融合在单线程回调里多次等待 TF，会阻塞 TF/深度消息处理。`tf_timeout_sec` 改为 0，由已有 pending/timer 机制重试。
- 可视化对未定位输出显示 `unavailable`、同步差 `N/A`，不再错误显示 base 和 0 ms。

## 验证结果

- 压缩 RGB 实收约 27–30 Hz。
- 修复 TF 等待前出现 1–2 秒有效样本延迟及较多超时输出。
- 修复后 8 秒采样收到 33 条输出，33 条有人且 map 有效，常见 16–17 个有效三维关节，TF 来源 `tf_exact`。观测年龄约 0.62–0.71 秒，含两机时钟残余偏差，不能直接等同真实算法延迟。
- 人体中心示例 base `[4.7875, 0.1292, 0.7253]` m；map `[4.7879, 0.1287, 0.7653]` m；平面距离 4.7893 m。坐标代表肩/髋中心，不是脚底落点；尚未用尺测精度。
- RGB/深度配对差有约 0.15 ms 和 33.2 ms 两类，仍处于配置 50 ms 窗口内；运动实验需检查跨帧配对误差。
- `rtsp://192.168.144.30:8555/pose3d` 经 ffmpeg 成功解码 2 帧，1280×720 H264。不是只检查端口。
- 几何测试 4 passed；首次 pytest 被全局 ROS 插件缺少 lark 阻断，关闭无关插件自动加载后通过。
- 遥控器 ADB 已授权。原控制应用显示旧 URL `rtsp://192.168.144.25:8554/main.264`，点击未进入编辑状态，未修改原控制地址。使用已有 VLC，显式传 `video/mp4` MIME 启动 StartActivity 后进入视频界面；最终遥控器截图已确认显示真实人体、骨架、关节距离、base 坐标及 map 状态。截图样本 D3=4.74 m、Dxy=4.68 m、base=(4.68,-0.00,0.74) m。当前为独立播放器，不是原控制应用内嵌。

## 下一步命令

当前推理已启动；不要重复启动。重启后可执行：

```bash
scripts/run_duct_pose_3d.sh rviz:=false
```

只读采样（另一个终端）：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=8 RMW_IMPLEMENTATION=rmw_cyclonedds_cpp
export CYCLONEDDS_URI=file:///home/yhc/kaiti_yolopose_framework/configs/cyclonedds_duct_workstation.xml
python3 scripts/check_duct_pose_3d.py --seconds 20
```

遥控器打开标注视频（在已配置 adb 的电脑执行）：

```bash
adb -s 192.168.144.20:5555 shell am start -a android.intent.action.VIEW \
  -d rtsp://192.168.144.30:8555/pose3d -t video/mp4 \
  -n org.videolan.vlc/.StartActivity
```
