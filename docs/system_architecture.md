## 感知、任务、规划与反馈

| 模块 | 输入与输出 | 实现及部署边界 |
|---|---|---|
| 语义事件感知 | 视频 → 关键点、32 帧 LSTM、稳定候选、置信度、源时间；低质量窗口需保留未知状态 | src/yolopose 下的 pipeline 和 temporal；通用 ROS2 骨架可使用 mock、视频或 ROS 图像 |
| 机器人任务生成 | 候选与显式核验、位置与空间资格 → 任务身份、目标、版本、依赖、激活和释放 | [事件协议](event_task_protocol.md)和 [Clinic 视觉桥](system_clinic_visual_input.md)。核验、监护、取送采用相同事件身份 |
| 多智能体协同规划 | 可执行任务图、能力、预计可用时间、旅行代价、资源、当前执行承诺 → 归属、顺序、开始/结束时刻、预约 | [Clinic 分配契约](clinic_dynamic_assignment_contract.md)区分冻结离线策略和运行时授权。MILP 和约束验证器使用一致的任务图 |
| 执行与动态协调 | 计划、任务版本、现场资格 → Nav2 与 worker；真实到达、服务、取消、资源反馈 → 新规划快照 | 使用实际 ACK 推进依赖，活动任务、监护、货物归属及取消待确认保留在活动前缀；检查版本后才能接受新计划 |

## 关键跨层约束

- 源观测、接收、核验、任务释放、执行就绪和服务完成分别记录。显式核验结论释放响应任务；到达或规划时刻本身不产生确认。
- 人体代表位置在任务空间接口中维护。当前 A 区来源为视频区域注册。服务目标须独立检查地图、资源、接近/清空、路径和站位；定位或目标过期时阻止新的不合格派发。
- 规划同时表达核验依赖、监护覆盖取送、取送同机、监护与输送异机、整段资源互斥。执行端检查实际反馈，任务在各机器人上异步推进。
- 调整只处理合法后缀。局部修复按依赖、机器人序列和相关资源传播影响，必要时使用同样保护承诺的全后缀重规划。取消待确认期间保留原执行身份与占用。在线配对可将提交前的一次路径拒绝写回该轮路线约束，重算后再次核对路径、承诺和资源。派发后的跟踪失败由原执行器处理。[实现边界](research_scope_and_completion_plan.md#内容三当前做到哪一步)
