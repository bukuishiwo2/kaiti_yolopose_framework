# 研究技术路线

以[研究范围与完成计划](research_scope_and_completion_plan.md)为验收依据。默认使用已验证的 YOLO Pose、骨架特征、LSTM 和稳定器。补实验优先覆盖漏点、遮挡、观测时效和任务误触发。任务生成沿用事件协议，先验证事件位置、目标资格和条件释放如何改变任务图，再用该任务图研究跨机器人能力、资源和异步依赖下的分配与排程。

## 参考论文的方法迁移

参考资料来自本地“毕业论文pdf”，原件作为阅读资料保留。以下标明实际采用的位置及仍需验证的环节。

| 来源 | 可复用原理及项目落点 | 验证方式 |
|---|---|---|
| 《基于线性时序逻辑的多机器人自动部署研究》第 3.3、4.2 节 | 执行中插入临时任务，完成后恢复后续任务；从机器人预计可服务时间评估协作请求。用 Clinic 现有投影位置、ready、路径先验、能力与承诺构建快照，B1 保持已有常态任务归属并枚举合法插入，B3 联合重排合法后缀。保留集中式现有实现 | 复用[耦合对照](../experiments/clinic_coupling_necessity/report_2026-11-23.md)的不可用机器人、期限与资源用例。从同一活动 E1 快照插入 E2，报告何时简单插入足够、何时联合改变分工以及对交付和常态任务的代价 |
| 《面向复杂时序任务的空间站内多机器人自动部署研究》第 3–4 章 | 用形式化时序表达联合动作义务。将 Clinic 的核验后释放、监护覆盖、同机取送和资源互斥编译为任务图及 MILP 约束，用已有[轨迹监视器](../experiments/clinic_multievent/trace_monitor.py)独立验收事件绑定和时序 | 对照成功轨迹、交付前监护中断、事件错绑、区间重叠及前缀未终止；分别验证计划与实际 ACK 轨迹 |
| 《多医疗服务机器人任务分配与路径规划研究》第 3.1–3.2 节 | 动态任务代价同时考虑响应需求、行进和当前负载。使用 Clinic 现有响应、旅行、常态等待及已接受计划变化项，并单独报告资源等待、响应和负载分布 | 对给定 G1 占用和机器人 ready 作成对反事实，保留原共同目标与强基线，记录响应、常态等待、交付及计算成本 |

相关论文的性能结果仅用于理解各自场景。项目采用既有 Nav2 和交通协调、有限时序监视与 MILP；参考论文中的乘积自动机路径搜索、Petri 网部署、合同网学习和自适应 A* 无需引入。旧感知路线的网络候选和训练扩展建议可从 Git 历史追溯。
