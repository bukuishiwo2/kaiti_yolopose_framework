# Clinic研究内容一二三串联可行性评审（2026-11-18）

## 目标与判断

本轮目标：判断能否让同一个Clinic仿真中的真实视觉语义结果改变任务生成与多机器人决策，替代执行器直接注入跌倒。固定三项研究内容：①环境认知与人体行为感知；②语义事件构建与任务生成；③多智能体协同任务规划。重点仍是第三项中动态变化后的承诺保护、局部修复和可执行性恢复，不另起研究主线。

**存在明确的复用路线，值得继续接入；但当前实现不能直接运行并声称已完成123视觉闭环。**本轮完成部署源码/资产预检和离线反事实验证，发现7类阻断。现有语义任务有效性可以影响分配/排程，空间语义尚未贯通。识别仿真人体是否可靠、运行吞吐和在线取消/承诺衔接仍未验证，不能保证仅接几个topic就能成功。

先读的依据包括仓库AGENTS、[11月17日交接](codex_handoff_2026-11-17.md)、[研究边界](research_scope_and_completion_plan_2026-11-09.md)、[最新稀疏配对及模式报告](../../reports/benchmarks/clinic_sparse_repair_and_modes_2026-11-17.md)、[完整闭环复验](../../reports/benchmarks/clinic_unified_full_loop_recheck_2026-11-17.md)、[局部修复贡献评审](clinic_local_repair_contribution_and_next_experiments_2026-11-17.md)，以及实际工作区两份当前运行/模式手册。较旧架构文档只作历史背景。

实际部署位置是`/home/yhc/clinic_planning_ws`；源码快照`experiments/clinic`本轮不修改。没有启动仿真或实车，没有更改现有ROS规划主链、MILP后端、Clinic配置和成功运行。

## 部署源码与资产预检的7类阻断

1. **事件与持续观测仍由控制器制造。**`tools/run_dense_episode.py:Episode.tick/inject_event`根据各机首项完成及至少两机正在导航触发事件；继承的`tools/run_aligned_episode.py:Episode.observe`把配置中心和固定服务点写成confirmed，按执行器时间刷新。视觉模式必须关闭这两条旁路；无新图像证据时只推进时钟/有效期，不能定时补造confirmed。
2. **相机模型存在，但图像链路没有接入统一入口。**`support/clinic_runtime/bootstrap.py`实际使用`config/three_tb4/r*.urdf`创建机器人；三份URDF都有`rgbd_camera`，320×240、1 Hz、`oakd_rgb_camera_optical_frame`。world已有Sensors系统。`launch/clinic_experiment.launch.py`只显式桥接时钟/真值位姿/激光，没有RGB、深度、CameraInfo桥接及感知消费者。URDF存在不能证明Gazebo图像正在正常发布，具体topic和QoS必须短测发现，不能猜测后宣称接通。
3. **时序采样存在明显不匹配风险。**1 Hz下32样本约需32秒采满（首尾约31秒），尚未计入调度/掉帧和稳定化。不能只改传感器频率就认为LSTM有效；需要核对训练采样、源时间戳、实际推理吞吐、时间窗和遮挡质量。本轮不改采样、不换LSTM、不重新训练。
4. **当前world没有显式人物/actor入口，跌倒动作尚无已验证素材。**本地已有Clinic人物模型，如`/home/yhc/rmf_clinic_ws/clinic_models/ElderMalePatient/model.sdf`；另有缓存`openrobotics/models/actor - relative paths/2/model.sdf`及其本地网格/动作，声明stand、walk、sit_down、sitting、stand_up等，未声明fall。后者适合先验证可见人体与非跌倒负例；不把“有人物资产”写成“已有可识别跌倒动画”。本轮没有遍历全盘并证明所有位置都没有跌倒素材，也没有下载/复制第三方大资产。
5. **空间结果被编译器覆盖。**`tools/dense_tasks.py:event_tasks`按role固定映射V1/M1/G1/H1，未把协议`target.xy`编成实际位置；`phases`又从锚点配置取location。`Bot.dispatch`继续从锚点取导航目标。离线已复现位置移动1米但优化几何和解完全不变；仅协议revision更新。必须同时对齐任务目标、导航目标、入场/清空点、旅行时间、共享资源与失效规则，不能只改JSON中的location。
6. **核验反馈没有真实视觉判别来源。**`run_aligned_episode.py:Bot.feedback`对核验服务succeeded直接写`result='fall'`。视觉实验必须区分“已到达/服务完成”与“确认为跌倒”；负例不能也自动进入监护/取送。可以复用同一视觉通道提供核验结果，但要标清重复使用同一证据并非独立二次确认，更不能据此声称临床诊断。
7. **证据退化与承诺保护尚未统一在线验证。**协议空间过期会使活动监护进入`CANCEL_REQUESTED`，在取消ACK前仍保留承诺；现有Clinic则持续用合成确认维持位置有效，尚未覆盖该真实退化路径。短遮挡应维持身份及有限TTL内有效位置；长期失效应禁止新移动任务并进入明确的安全恢复/核验流程。监护、携货与已发指令何时允许取消、如何交接必须明确，不能把通用取消请求直接当作释放硬承诺的许可。

这些是集成阻断/方法验证缺口，不是为了新论文题目重新设计感知、事件和规划三个系统。

## 本轮已完成的最小因果检查

详见[离线结果](../../reports/benchmarks/clinic_semantic_counterfactual_2026-11-18.md)：9类手写协议用例、3次唯一完整请求的既有MILP求解，21项诊断检查通过；协议专项21项测试通过。有效事件除增加verify外，还把同快照的一项常态任务从R1改派R3，说明规划并非只显示一条告警文字。重复观测、短遮挡不重复建任务；位置无效/过期不放行未执行的事件移动任务。

**人工协议输入不属于视觉证据。**因此本轮只能确认“现有语义入口有能力改变决策”，未证明“仿真感知结果已经改变决策”。整链准入状态明确为false。活动监护失效仅测到协议取消请求，没有实际取消或修复执行。

## 下一阶段的单一场景与最小接入路线

沿用同一20×25米Clinic区域、三机、常态任务、服务ACK、床短阻挡/持续阻挡和研究后端；视觉实验使用独立显式输入模式与新运行目录。原Benchmark和Fast/Standard继续冻结，旧成功结果不回写，也不新增第二个任务拥有者。以下为待实现/待验收路线，不是已经运行的系统。

```text
仿真可见人体动作 → TB4的RGB/深度/CameraInfo及源时间戳
    → 既有YOLO Pose / LSTM / 稳定化 / 观测质量
    → 同时刻深度+TF空间关联 → 有效服务点/经验证候选点
    → 单一event-task/v1实例 → 现有任务编译适配
    → 原MILP分配与排程 → 既有Nav2和服务反馈
    → 实测变化使计划失效 → 承诺投影/局部修复 → 执行恢复
```

**阶段A：先用一个相机的最小感知短测定位风险。**先离线审查已有动作/模型文件和三维融合配置，复用本地人物素材；在不派发研究任务的隔离短场景中验证RGB/深度/内参、光学坐标、同步和真实图像可见性。先站立/坐下负例，再验证一个完整受控跌倒序列；若现有素材不足，先报告动作资产缺口。刚体人物直接放倒只能算受控倒地姿态测试，不能冒充真实跌倒运动或用其绕过LSTM时序。保存少量必要原始帧、模型输出和源时间戳，失败先诊断，不自动启动三机完整巡逻。

可由脚本控制人体动作或床的位置，作为实验刺激；**脚本不得向事件层直接发送fall/confirmed，也不得泄漏人体位姿真值来代替视觉定位、提供固定核验结论或按时间表强制出任务。**人体真值只给独立评测器。机器人定位可以继续采用既有Gazebo参考定位，但必须标注，不能借此声称RTAB-Map/AMCL性能。

**阶段B：独立适配、离线回放，再短集成。**复用既有`PoseRunner`、ROS图像输入、`pose_3d_fusion_node`及几何工具，不启用旧S1脚本作为隐式依赖。适配单活动事件身份、仿真时钟与源时间、质量/缺失、TTL及显式核验结果；只在真实有效新证据时更新观测。事件ID、观测/空间revision、任务ID、计划版本、导航/服务执行token须可关联。

空间先复用已审核服务点库：用视觉估计位置判断属于哪个有效服务区域，距离/质量不满足则拒绝释放，不默认回落固定V1。区域选择仍是有限场景适配，不能称任意点在线安全目标生成。若要求位置变化驱动不同分配/排程，至少准备两个事前几何验证过的区域/服务点组及对应路径时间/资源映射；第二组在本轮尚未建立。后续可复用Nav2路径查询获得旅行代价，避免重建规划器。

感知目标修订时，未下发任务可更新；已下发任务、监护和携货必须先按当前承诺检查，存在冲突时进入安全恢复/经ACK的合法转移。提交前再次检查证据有效期及执行状态，旧revision解不得直接发布。

**阶段C：通过离线与匹配短门禁后，才选单次必要的完整视觉闭环。**用既有路径/到达/ACK护栏验证所选服务点；显式修订视觉模式审计，不能让它继续强制要求`fall_event_injected`或“已做完三机首项才允许发生跌倒”。若希望事件发生在巡逻中，可以控制人体动作发生窗口，事件成立仍由感知决定；检测漏失必须判失败，不能超时自动注入兜底。之后保留实体床观测导致旧计划失效、活动承诺保护与恢复链路，继续服务于内容三。

## 整链验收与反事实证据

同一已记录视觉/深度/位姿证据、相同机器人快照、相同后端用于离线反事实；物理闭环分叉后不能再声称状态完全一致。至少记录如下预先定义的组别，负例也进入结果：

| 输入/变化 | 期望任务层结果 | 期望规划/执行证据 |
| --- | --- | --- |
| 站立、走动、坐下或空场 | 不产生跌倒事件移动任务 | 常态计划继续；误报/延迟如实记录 |
| 真正被YOLO/LSTM识别且稳定、已定位的受控跌倒 | 先verify；有明确fall核验结果后再monitor/pickup/deliver | 机器人能力、常态负载、监护覆盖与同车取送共同影响分配和时序 |
| 同样高跌倒置信度，但深度/TF无效或过期 | 不释放带假坐标的移动任务 | 无无效目标派发，信息恢复后再规划 |
| 短遮挡/重复观测 | 保持事件ID和合法承诺、不重复建任务 | 无无谓重派；超过有效性边界按定义恢复 |
| 两个事前验证的事件区域/目标变化 | 服务点、旅行代价/资源随视觉空间证据变化 | 输入和分配/排程变化可追溯；若最优归属未变，也应展示真实目标/时序变化，不强凑换机 |
| 活动监护及携货期间持续床阻挡 | 执行观测导致旧约束失效，必要修复 | 原监护/包裹/已发指令身份保持，后缀恢复可执行，未受影响常态工作继续 |

证据表必须沿`图像源时间→模型分数/稳定状态/质量→事件与位置版本→任务图→规划输入→分配/排程→实际执行/反馈→失效原因→修复发布`保存完整关联。关键反事实：关闭语义输入应无应急任务；保留分类但移除有效空间信息应禁止移动；改变有效空间证据应改变实际目标及对应规划条件。仅“topic连通”或“视频里出现倒地人”均不满足。
