# 研究内容三的时序逻辑采用评审

## 结论

建议将有限轨迹线性时序逻辑（LTLf）接入 Clinic 的离线执行验收。研究内容三仍以语义事件驱动、考虑执行承诺与任务依赖的动态协同分配和重规划为主。任务图描述依赖，MILP 决定机器人、顺序与时刻，Nav2 执行移动，LTLf 从实际反馈验证跨机器人、跨重规划版本的任务义务。首轮只验证这项接入是否增加可解释的时序证据。

## 最小验证设计

1. **核验与响应分支。** 有效候选须进入核验流程，撤销或证据失效须有明确终态。阳性复核前禁止派发后续应急服务。阴性复核须关闭当前事件并禁止该次响应。阳性在适用的正常终态须完成取送、交接与释放。明确中止和正常完成各自的判定条件。
2. **持续监护与交接。** 监护进入活动状态后才可启动取货服务。保持该事件的有效监护直至真实交付和交接凭据具备，再允许结束监护。机器人身份、token、版本、位置和 ACK 的一致性由协议及原独立验证器核对，监测器读取经归一化的事件级事实。
3. **重规划后的常态任务。** 被承诺且暂停的常态任务，依据场景须恢复或有明确合法取消。可先利用床场景中的“真实清空和资源释放之后才派发关联常态任务”作具体反例。每次重规划继承此前实际发生的监测状态。

先离线回放 A 区正例、负例和实体床成功日志，再制作人工反事实副本，删除交接/核验 ACK、提前释放监护、交换事件 ID、把预测完成伪作实际完成，或在中途截断。保存每条规则的触发覆盖、首个违规及来源、未决义务、正确判定比例和回放耗时。规则未触发应单列，证据不足与业务违规分别记账。与现有审计并行，记录结果是否一致，以及哪类发现来自新增时序规则。时间源统一使用运行日志的仿真时钟，求解耗时继续使用壁钟。

预期改善的是跨模块时序违规的可定位性、重规划前后义务的一致验收和不同策略的可比性。更快响应、更少改派及更低修复耗时仍须用公平分配和重规划对照实测。相机误报、RGB-D、B 区可达性和活动服务安全恢复各自需要对应的观测或执行证据。只有出现固定 DAG 难以表达且会改变分配决策的可选任务结构，才值得评估规格到 MILP 的编译或自动机合成。
