日期：2026-11-18。依据用户最新研究定位，本轮只审查实际模型、运行入口和既有证据，不修改MILP目标、权重、约束、Nav2、服务worker或规划主链，不启动新仿真。

## 1. 固定研究目标及A/B关系

研究内容三保持为**面向动态语义任务的多智能体协同分配与重规划方法**，推荐核心方向为**语义事件驱动、考虑执行承诺与任务依赖的动态多机器人任务分配方法**。其目标是兼顾应急响应、常态任务连续性、完成效率和不必要改派，而非围绕修复求解器形成独立主体。

- **核心问题A——事件出现后如何合理分配。** 以原MILP为基础，利用内容二提供的任务图、任务条件与有效空间信息，结合能力、预计可用时间、已有工作和共享资源，联合选择机器人与服务时序。
- **核心问题B——已开始执行后如何合法调整。** 在同一分配模型中投影不可撤销执行前缀及资源承诺，限制允许变更的任务；环境变化使计划不满足约束时，以局部修复或合法回退保障恢复。

B服务于A的实际可执行性，不另拆为第三个算法。局部修复、种子门槛和范围扩展保留为支撑机制、实现限制及消融因素。前轮36实例的正负结果完整保留，但后续优先级从“继续修复求解机制”转回“动态分配决策本身的独立证据”；不将原修复性能数据改名为语义分配贡献。

内容二确定事件是否有效、任务何时生成、依赖与执行前提；内容三接收这些条件，决定谁执行、何时执行、允许调整哪些尚未执行任务。没有新的事件理解、三维定位、紧急程度推断或跨源融合成果被本轮审查补造出来。

## 3. 现有目标函数到底优化什么

原目标和独立复算位于[backend的objective](/home/yhc/clinic_planning_ws/tools/clinic_milp_backend.py:269)。实际Clinic快照经[dense_tasks覆盖权重](/home/yhc/clinic_planning_ws/tools/dense_tasks.py:48)，不是直接使用文件顶部默认值：response从1改为4，shift从0.25改为0.05。

实际权重为：travel=0.1、normal_delay=0.1、response=4、wait=0.01、energy=0.1、owner=2、shift=0.05、adjacency=1、return=0.01。

| 现有项 | 精确定义 | 应如何表述 |
|---|---|---|
| travel | 被选机器人路线弧的旅行时间之和 | 服务锚点间旅行先验代价，不是在线多机器人联合几何路径优化 |
| normal_delay | 常态任务`sum(start - release)` | 从释放到开始的等待，不是`max(0,finish-deadline)`意义的逾期惩罚 |
| response | 每事件`monitor_start + deliver_finish - 2*observed_at` | 监护开始响应与配送完成响应的和；不是核验响应，也不是单一末端完成时间 |
| verify_response | DenseModel额外加入`verify_start - problem.time` | 核验从该次规划时刻到计划服务开始的等待，权重同response |
| owner | 参考任务归属发生改变的数量 | 仅参考集合内的任务；新应急任务首次分配本身不算改派 |
| shift | 参考任务`sum(abs(start - old_start))` | 计划开始时间变更；参考开始时间必须有明确来源 |
| adjacency | 参考路线相邻任务对在新路线中丢失的数量 | 序列变更代价，不能等同换机数 |
| wait | 路线弧上的等待时间之和 | 非独立的负载均衡目标 |
| energy | 旅行、等待和服务能耗 | 原模型有表达能力，本场所有相关耗率为0，不能据此声称做了电量决策 |
| return | `sum(route_end - robot.ready)` | 路线工作跨度之和；当前是open-route，虚拟END旅行为0，不等于返航，也不是makespan |

结论：用户建议的四项框架**部分已有、部分需要明确或补齐**。应急响应、常态等待、改派/变更已有；显式最大完成时间、任务总完成代价、真正逾期惩罚和负载均衡未作为当前四项目标完整实现。不能将return项改名为已实现的`C_completion=Cmax`，或将有时序约束表述为已有负载均衡算法。

本次真实响应快照有一个额外解释风险：6项常态任务的reference start均退回release=0。由于这些任务还没有旧的已接受开始计划，其shift=142.487，恰好是normal_delay=284.974的一半（权重0.05/0.1）。这一次两项都惩罚从0开始等待，并非两种独立连续性损失。[参考构建](/home/yhc/clinic_planning_ws/tools/dense_tasks.py:60)对尚无旧开始时间的任务用release回退；后续修复才使用当前计划trim。应区分“首次分配参考名义归属”和“重分配参考已接受计划”，不要把回退参考的shift全部宣传为减少已有计划扰动的收益。

## 4. 响应起点与期限口径

原始证据中的Clinic时间：候选建立43.87，核验规划43.89，核验任务release43.87，预测核验服务开始169.00；显式fall复核后任务release172.26、响应规划172.29。源视频第3.3秒属于另一时钟，不作Clinic事件发生时间。

因此原核验代价使用125.11秒，而从候选到预测开始是125.13秒。本例差仅0.02秒，但重新求解时若仍用新的problem.time起算，跨调用响应指标便不可直接混用。监护/交付目标则从最早候选43.87起算，而非fall复核172.26；这两种起点目前同时存在。以上均是保存计划中的预测数值，不替代真实服务ACK时间。

11项探针还验证：只将event.observed_at增加10秒，约束、变量域及目标系数均不变，目标常数减少80。它改变报告数值，却不改变同一输入条件下方案的排序。**不能把observed_at字段解释成已实现“事件越久优先级越高”的动态决策机制。**

建议在实现新目标前先冻结以下时间契约，本轮尚未修改代码：

| 时间字段/评价 | 建议语义 |
|---|---|
| candidate_at | 首次有效候选在Clinic系统建立的时刻，保持不变；不是源视频相对时间 |
| confirmed_at | 带来源的fall核验结论被接受的时刻，不由服务成功自动生成 |
| task_planning_release | 该角色首次满足语义生成条件且可进入排程的时刻；PENDING的未来任务仍可参与联合排程 |
| execution_ready | 依赖、有效目标及监护运行等实际守卫均满足的时刻，区别于允许提前排程 |
| 核验响应 | 实际verify服务开始减candidate_at；同时分开列任务生成、求解、不可中断前缀等待及导航耗时 |
| 监护/取送响应与完成 | 同时列从candidate_at起算的端到端指标、从confirmed_at或首次角色release起算的阶段指标，不能选择有利起点拼表 |

目标函数使用哪个起点在单次固定任务优化中常只是常数区别；评价口径、跨事件优先级和跨阶段比较仍必须固定。若以后引入按等待时间变化的紧急程度，则应明确系数或期限如何随时间更新，而不是仅减一个时间戳。

另有编译口径待处理：[compile_tasks](/home/yhc/kaiti_yolopose_framework/src/kaiti_task_sim/clinic_visual.py:108)每次以传入now设置release和`now+360`开始截止。对完全相同planning view在1秒和2秒编译，release和截止均平移1秒。当前未直接继承协议generated_at作为固定时限起点；不能宣称已经实现了不可被重复观测推迟的事件响应期限。后续应先明确期限属于首次任务还是任务有效修订，再调整，不能本轮直接改动既有成功条件。

## 6. 哪些是一般快照优化，哪些确实由语义事件驱动

基础MILP在每次调用时求解一个确定性的静态快照，这是现有建模方式，不代表整个框架只能做静态分配。动态性来自任务集合、依赖、有效服务点、机器人前缀与占用随事件/执行反馈重建，然后重新求解和受控提交。

当前已真实贯通的因果作用包括：

1. 原YOLO/LSTM稳定候选，经唯一event-task/v1且位置有效，才出现verify；服务成功本身不能生成fall结论。
2. 显式fall核验后才生成monitor/pickup/deliver；no_fall关闭并停止全应急任务扩展。
3. 任务角色带来能力要求、先后、覆盖和同车/分离关系；这些关系会改变优化约束，不是仅显示告警。
4. 独立视觉编译器按有效注册区域选服务点、entry/clear与旅行表；A/B空间实体资格仍不完整，不能把原固定锚点问题的修复说成任意人体三维定位。
5. 真实执行状态更新前缀和资源可用性；新计划必须通过版本与实际ACK守卫，不能覆盖既有承诺。

11项原生模型敏感性探针的结果为：

| 单独改变的输入 | 对当前模型的观察 |
|---|---|
| event/task的priority、urgency | 变量域、约束、系数、常数均不变 |
| event的confidence | 全部不变；不否定上游稳定/核验门控的价值 |
| robot的workload标量 | 全部不变；已有工作仍可通过ready等间接影响 |
| robot.position但source_anchor不变 | 全部不变；应通过合格状态投影/旅行代价更新影响规划 |
| observed_at单独+10 | 仅目标常数−80，无排序变化 |
| response权重 | 目标系数改变 |
| ready、来源锚点、能力、依赖、资源不可用区间 | 约束/变量域改变；来源锚点也改变旅行目标系数 |

这些探针是对原生输入的受控审查，不是真实感知实验，也不是性能对照。不能由“添加一个未消费字段不生效”推断系统完全不利用语义；正确结论是**语义目前主要通过任务生成与关系/位置约束进入分配，尚未形成任务紧急度数值驱动的策略。**

## 8. 可以形成贡献的核心：统一的合法插入与联合分配

建议围绕**一个主体方法、A/B两个相互关联问题**组织后续研究，而不是再提出一个求解器算法：

1. 由内容二给定事件任务图、角色时窗、有效服务区域与核验阶段；内容三不重复研究事件协议本身。
2. 把每台机器人已执行、已下发及不可中断工作投影为不可变前缀/资源约束，形成真实可用时间和剩余候选域；未下发工作进入可调整后缀。
3. 在同一MILP中联合优化合法的应急插入位置、任务owner、协作角色和常态后缀时序，显式权衡响应、完成、常态损失与真正已有计划的变更。
4. 新任务/有效任务图变化触发动态分配；只有已有计划被后续环境/状态变化判为不可行时，才使用必要的局部范围修复。旧计划仍满足新约束时，不制造失效或强制扩大修复。
5. 独立约束验证、版本/token/ACK门禁保持同一约束语义后提交；承诺不能通过高惩罚项被优化器“买断”。

目前具备其中的大量实现基础，但“语义任务依赖＋执行前缀＋应急/常态联合优化”的作用还需单独对照，不能把模块齐全直接等同创新成立。新增一个多目标加权和也不足以单独成立创新；应验证它在特定动态条件下改变了什么决策、减少了什么损失，以及付出了多少等待/改派代价。本轮未做新的文献新颖性检索，不声称文献空白。

用户四项目标可作为后续清晰的数学表达：

`J = α C_response + β C_completion + γ C_delay + δ C_reassignment`。

但正式实现前需要决策并冻结：completion选事件交付完成、全任务makespan还是任务总完成代价；delay选释放等待还是相对名义服务时刻的迟延；reassignment仅计算已有接受分工的任务；时间/数量单位及权重尺度保持可解释。旅行成本和必要序列变化可保留为次级项，不为匹配四个符号删掉原执行所需的约束。负载先作为状态和评价指标，只有研究假设明确才新增公平项，不能同时堆叠大量目标而无法归因。

## 9. 下一组应优先验证A，B作为共同合法性条件

优先做**同一语义任务集合、同一执行快照、同一硬承诺/DAG/资源/资格域**下的离线分配对照；暂不继续扩展床实验或求解器性能表。

| 对照 | 用途及公平性 |
|---|---|
| 固定名义分工＋重新排程 | 静态分工强基线；遇能力/时窗冲突如实不可行，不能把拒绝服务藏掉 |
| 能力可行的预计最早可服务贪心 | 考虑ready、旅行和合法插入，完整检查DAG、监护覆盖及资源；比单纯最近机器人更强 |
| 当前受限事件插入MILP | 保留现有开放范围和第三角色政策，量化当前方法实际解决的问题 |
| 候选承诺/依赖约束下联合动态分配 | 只开放合法未下发任务，使用相同原MILP；先验证增加自由域是否带来响应/常态代价的合理改善 |

主比较必须同预算、同目标、同任务/硬约束；同目标全自由模型是质量参考，不能另换成弱基线后称全量更差。若单独移除依赖或承诺做消融，其数学可行域已改变，应将其结果送入原完整约束检查器，报告不可执行率、冲突和错误取消倾向；只用于离线机制诊断，不允许真的下发非法方案，也不能将放松约束的低J直接当性能优势。

建议先覆盖以下机制，再预先冻结参数种子/规模：距离最近者有不可中断任务；备用机器人具有共享能力但常态负载不同；监护持续占用造成取送与常态竞争；共享G1占用导致协作排程变化；硬承诺下不可恢复应正确拒绝；同一快照仅改变已正式定义的语义紧急级别。多事件竞争需先明确单事件协议边界，不能用虚构第二事件冒充当前整链已经支持。

主要评价应包括：实际/预测分开的核验响应、监护响应、事件交付完成、全任务完成、常态等待/延期、任务归属与序列变更、承诺/依赖/资源违规、分配成功与拒绝原因，以及求解开销。性能阶段分别报告规划求解和实际Nav2/服务时间；事件出现越晚、不可取消前缀越长不能被解释为算法自身求解更慢。

离线证明不同合法选择有实质差异后，再对必要的角色组合补空间资格，选择少量代表例做实体对照；不要求先修好B区或完成RGB-D，但不能把唯一已资格化的分工当作自由分配的实体性能证据。
