# 三项研究内容与论证逻辑校正

日期：2026-11-02。固定题目：《动态环境下融合语义感知的多智能体协同规划研究》。本文按用户最新明确要求校正此前两轮评审，不修改冻结实现方案。

九月全景说明已明确：一是视觉检测；二是事件稳定与任务层形成，三维落点、安全区、服务点、动态资源和任务模板均在其内；三是单/多机分配排程与修复。用户本次明确将 SLAM 环境认知纳入第一项，这应作为最新的论文层级解释。

此前把“动态通行预测”单独设为第一项、把第二项收缩为序贯推断、把第三项替换为主动核验联合规划，均改变了研究边界，撤回作为主线调整的建议。它们最多是经论证后可选的方法，不是用户已有研究内容。

## 2. 正确的论文逻辑

每项采用：**相关研究及其适用条件 → 本课题具体未解决的问题 → 研究内容与方法 → 方法差异及性质 → 外部比较与消融 → 支持何种创新结论**。

这条链不等于“先认定三个创新，然后倒推研究空白”。先确认三个问题和研究边界，再查明哪些具体方法差异能够成立。已有技术可以是基础，但不能直接改称创新。

| 层次 | 核心问题 | 本层输入 | 本层输出 | 不越界的职责 |
|---|---|---|---|---|
| 一：环境认知与人体行为感知 | 机器人如何获得可信的环境、位姿和人体行为证据？ | RGB-D/激光/里程计、连续图像 | 地图、位姿、人体框/姿态、行为分数、质量信息 | SLAM 与 LSTM 等感知方法；不直接创建处置任务 |
| 二：语义事件构建与任务生成 | 如何把连续、不确定的证据变成稳定且可执行的任务描述？ | 一的输出与事件历史、动作模板 | 事件实例、地图位置/区域、有效性、服务目标、安全/资源约束、任务及依赖 | 决定产生什么任务、在哪里做、前提是什么；不决定分给哪台机器人 |
| 三：多智能体协同任务规划 | 给定任务和约束，如何合理分配、排程，并应对变化？ | 二的输出与机器人能力/电量/状态 | 分配、顺序、时刻、资源预约、修复计划 | LTL 规格、MILP 与动态重规划；不重新代替上游识别和任务解释 |

SLAM 输出原始地图/位姿属于一；利用位姿与深度把人体证据绑定为“地图中的事件”属于二。连续人体三维点是感知输出，事件身份、有效期、区域及任务约束是语义抽象；不必为每段代码机械规定论文归属，但要固定输入输出，避免同一方法重复主张创新。

## 3. 问题一：动态环境中如何可靠感知环境与人体行为

### 从研究现状引出问题

需要分别综述几何 SLAM/动态 SLAM，以及人体姿态/时序行为识别，再说明移动机器人场景中二者面临的共同观测条件：相机运动、人员遮挡、远近尺度变化、缺失关键点、帧率变化。

动态 SLAM 已经处理运动物体对定位和建图的影响，不能写“现有 SLAM 都假设静态、无法处理人”。例如 [DynaSLAM](https://arxiv.org/abs/1806.05620)已有运动物体检测与静态背景建图。骨架时空建模也已有 [ST-GCN](https://arxiv.org/abs/1801.07455) 和 [CTR-GCN](https://arxiv.org/abs/2107.12213)，不能只把 LSTM 优于几何规则当作先进性证据。这些是代表性机制依据，尚不是完整最新综述。

本课题可验证的问题表述：**移动机器人观测下，环境定位误差、人体遮挡和采样不稳定如何影响人体行为识别；怎样获得对后续任务解释足够可靠的感知证据？**

### 研究内容与创新落点

保留现有 SLAM/定位基础与 YOLO Pose、LSTM。若争取本章独立学术贡献，必须在感知层形成明确改进，例如针对缺失关键点、相机运动或真实采样间隔的时序特征/模型/训练方法，并与同条件基线验证；不能仅改阈值、串接两个现成模块。

这是待查新的方法落点，不是已经提出新模型。无需强迫 SLAM 和人体识别各自再出一个创新：SLAM 可以是环境感知基础，本章创新集中于机器人视角下的行为识别。若实际仍完全复用现有模型，则本章是研究基础，尚不能保证“一章一强创新”。

### 对比与验证

- 保持地图/位姿来源固定，比较规则、普通 LSTM、TCN、至少一种适配的公开骨架时序方法与改进法；说明输入和预训练差异。
- 若声称改进 SLAM，才安排匹配数据/传感器条件的定位建图对照，报告 ATE/RPE、失跟踪率与动态地图污染；否则仅作为基础有效性验证，不要求超过专门 SLAM 方法。
- 人体实验分静止/移动相机、正常/遮挡、不同距离/采样率，报告事件级识别、延迟、误报与算力；测试集按人员/视频/场景隔离。
- 当前实车 32 帧在约 4—5 FPS 下覆盖的时间与训练数据可能不同，应先核查。这是明确可测的失效因素，但发现该问题本身还不是算法创新。

## 4. 问题二：如何把感知结果变成机器人语义事件与任务

### 从研究现状引出问题

应综述语义地图/事件表示、事件时序推断、任务生成与空间落地。分类器输出概率，语义地图提供位置/类别，任务规划器要求离散事实、目标、依赖与约束；它们之间存在需要显式建模的转换关系。

不能笼统写“已有方法不能把感知用于规划”。[Perception-Based Temporal Logic Planning](https://arxiv.org/abs/2012.10490)已经研究位置/类别不确定性和概率感知谓词。需要对比它及更接近的事件响应方法，核查事件持续、观测退化、重复检测、空间有效性与任务生命周期如何处理。

本课题具体问题：**同一人员行为的反复检测、短时遮挡与位置误差，如何转化为身份持续、时空有效且不会反复创建/误取消的事件，以及满足空间和逻辑前提的机器人任务？**

### 研究内容与创新落点

这一层必须完整保留：检测证据 → 稳定事件/episode → 地图位置和区域 → 安全区/可达服务点 → 任务模板与依赖。不能缩成分类分数平滑，也不能只做 JSON 字段转换。

学术贡献可在**不确定感知到事件—任务的统一时空抽象与生成规则**中寻找：明确事件出现、持续、退化、关闭条件；明确何种位置和观测条件允许释放何种任务；明确事件更新如何改变任务而不重复生成。

需进一步形式化状态变量、递推/关联规则和任务释放判据，并分析一致性，例如：同一活动事件不重复创建同角色任务；缺少有效空间目标时不释放相应移动任务；任务前提变更能追溯到事件更新。若只用数据库去重和版本字段实现这些性质，仍主要是工程正确性；要有区别于成熟事件模型的推断/抽象方法及相应收益。

### 对比与验证

- 直接检测触发、调优迟滞+模板、成熟时序推断+模板、当前四态+Episode及改进抽象方法，使用同一感知证据。
- 对外部语义规划方法，先定义可共同表达的事件与任务片段；扩展生命周期或空间约束时标明 adapted，不能把不支持的功能直接记成方法失败。
- 空间消融：区域中心、单点深度、稳健 RGB-D、带空间有效性约束的目标生成；这些是方法机制对照，不能仅凭反投影改进认定新颖性。
- 真值同时包含事件实例和人工复核的应生成任务：比较任务生成正确率/召回、重复与误取消、目标有效率、释放延迟；固定第三层规划器，再统计无效导航、计划震荡和任务失败。

## 5. 问题三：给定任务后如何合理分配与规划

### 从研究现状引出问题

应综述贪心/拍卖、时序逻辑多机规划、MILP 分配排程与动态修复。不能写成“现有方法只考虑距离、不考虑时序和资源”。[Calvo & Capitan 的 TRO 2025 工作](https://arxiv.org/abs/2411.02062)已有异构能力、电量、MILP 和在线计划修复；[2026 不确定任务需求耦合分配](https://arxiv.org/abs/2509.22469)也说明不确定需求与协同耦合已有研究。

具体问题：**在给定任务先后、持续留场、异地取送、共享通道、电量与期限时，如何联合分配排程；事件、服务点和资源变化后，如何在保持任务约束的同时减少不必要的计划扰动？**

### 研究内容与创新落点

保留原有序列 MILP、动态资源预约、局部修复/全量回退主线，不强行改成“核验前联合主动感知”的新研究题。学术贡献必须来自具体任务耦合的模型差异，或可分析的受影响子问题构造与求解方法，不能只说“LTL+MILP”。

建议先与最接近模型逐条比较持续监护区间、取送绑定、服务目标变化、跨机器人资源传播及执行承诺：哪些是标准约束，哪些已有，哪些在本问题中产生新的求解困难，再决定核心算法。

LTL 的预期角色可用于规范表达与满足性检查，但现有 [LTLf 门禁](../ltlf_tool_gate.md)明确只做有限轨迹验收，未参与任务合成或 MILP 分配。因此当前不能写“已完成 LTL 自动生成任务/自动机规划”。若希望 LTL 真正驱动规划，需要另行定义规格到任务依赖或约束的编译及正确性，这属于新增研究，不是换个表述。

### 对比与验证

- 基础：最近、优先级贪心、固定角色双机。
- 外部：已有约束分配/修复算法，在其共同能力子问题比较，再公开完整场景适配。
- 强对照：Full-Replan、Full-Replan+相同变化惩罚、时间顺延修补、当前 LocalRepair、改进求解法；统一硬约束与预算。
- 小问题用精确解验证可行性和最优性差距；扩大机器人/任务/扰动规模评价响应、完成率、违约、等待、能耗、修改量、全过程时间与回退率。
- 学术性质候选：约束保持、依赖边界充分性、终止或求解界；仅有旧 revision 拒绝和取消 ACK 不作为主要学术贡献。

## 6. 三项实验如何连接而不混淆归因

1. 验证一时固定二、三，判断感知质量是否改善；SLAM 与识别分别报告指标，不拼成一个不可解释的分数。
2. 验证二时回放相同的一输出，固定三，判断语义抽象和任务生成是否更正确、更稳定。
3. 验证三时输入相同且可追溯的任务、目标和资源状态，判断分配/排程/修复算法差异。
4. 最后在同一场景做端到端消融，验证局部收益是否改善最终处置。两个实体用于并发闭环，离散规模仿真用于统计与扩展性。

场景保持“识别—解释—协作”完整链：机器人巡检建图/定位与观察人体；正常/疑似/确认/遮挡后恢复；生成核验、监护和取送任务；动态通道、目标变化或新事件触发计划更新。加入无事件、无扰动、单机和固定双机对照，避免仅展示复杂成功样例。

统计沿用配对独立运行、冻结 test、相同调参预算、95% CI、失败与超时入分母；外部原版与适配版分开，不直接对比不同论文不同场景的百分比。现阶段没有新结果，不填写预期提升当实测。

## 7. 当前应形成的结论

三个研究内容和三个问题可以明确一一对应，但不等于三个创新已经成立。当前应先建立三张“最接近工作—假设与能力—本课题实证问题—拟改进机制—验证指标”矩阵，再按证据收敛方法。第一项尤其不能把现成 SLAM+LSTM 直接认定创新，第二项不能把接口串联认定创新，第三项不能把标准约束相加认定创新。

本次只纠正研究结构并给出论证边界，未更换模型、实现算法或修改冻结参数。变更文件：新增本文，给前两份评审增加纠正说明。风险：最接近方法全文与复现仍不完整，三个独立学术贡献尚待确认。
