## 3. 调整后采纳

### 3.1 安全项不作为可权衡的软惩罚

二次评审建议的目标包含 `R_safety`。本轮保留“必须形式化安全”的长处，但不允许求解器
通过降低 makespan 来换取安全违规：

```text
min J =
  α * C_max
  + β * sum(task_lateness)
  + γ * N_change
  + η * travel_and_energy_cost
```

核心 keepout、角色服务点、持续留场、能力和资源互斥全部作为硬约束。若后续需要优化
安全裕量，只能在硬安全边界之外增加次级软代价。

### 3.2 文献深化只针对真正进入方法的论文

接受“原矩阵偏摘要级”的批评，但不为 15 篇论文逐篇搬运与本项目无关的完整公式。本轮
深化 #1、#2、#3、#6、#12、#15，补充问题对象、算法链、验证重点、本项目变量和复现
边界。Hydra/Khronos/HOV-SG 等仍只作为结构或未来工作。

### 3.3 每机器人独立 keepout 由 P1 改为条件项

P0 的核心区对所有机器人统一禁入，因此共享 mask 已足够。只有未来明确存在某类机器人
必须进入核心区的需求时，才实现每机器人独立 filter mask。

## 5. 修订后的 P0/P1/P2 边界

### P0

- R1 携带 Orbbec 巡检、发现、复核和持续留场；
- R2 取送急救物资；
- YOLO11 Pose、LSTM、四态事件和 EventEpisode；
- Rule/LSTM/TCN 感知比较；
- 已知 2D 图、AMCL、Nav2；
- Robust RGB-D 事件落点及四级定位对照；
- 人工语义多边形；
- 不确定性膨胀的共享核心 keepout 和两个边界外服务点；
- 持续阻塞迟滞与路径缓存失效；
- MILP + 在线 LocalRepair + Full-Replan fallback；
- 单机器人、Full-Replan、无 keepout 和定位方法消融。

### P1

- R3 人群引导；
- Tiny Transformer；
- RTAB-Map 点云展示；
- 双事件和更多机器人压力测试；
- 自定义消息全面迁移；
- 有角色进入核心区需求时的独立 filter mask。

### P2/P3

- ST-GCN、PlanSys2、任务完成不确定性；
- Hydra/Khronos/HOV-SG 完整集成；
- 自动三维语义建图、开放词汇导航和通用人群预测。

## 6. 尚未解决的风险

1. Orbbec 驱动、D2C、内参和外参仍处于 `BLOCKED`，必须先通过台架门禁；
2. AMCL 与双机器人 TF/命名空间尚未实现；
3. 动态 keepout 的更新延迟和 Nav2 filter 链尚无实测；
4. 持续阻塞阈值是初始工程值，需要用日志校准；
5. 公共空间 hard-negative 数据规模和标注周期尚未确定；
6. 当前 ROS 在线路径仍未调用 LocalRepair；
7. 正常工期 10–14 周仍依赖 P1 项及时停止。
