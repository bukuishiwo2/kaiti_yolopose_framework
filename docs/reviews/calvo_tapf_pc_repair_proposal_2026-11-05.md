# Calvo 与 TAPF-PC 深读：面向耦合任务的局部结构—全局时序修复方案

日期：2026-11-05。

任务目标：深入比较第三项最接近的两项工作，结合现有项目提出可形式化、可否证的改进方案。本文只增加研究文档，不改代码、配置或冻结方案，不运行机器人与算法实验。

## 1. 推荐方案与当前判断

建议研究：**基于耦合边界可行域的多机器人局部结构与全局时序修复**。

核心区分是：**时序影响传播范围，不等于分配与排序需要重新搜索的范围。**

一次交付延迟可能使监护结束、另一任务开始和多个通道预约联动；这些任务的时间需要更新，却未必都需要重新分配或排序。建议保留大部分离散结构，允许未来连续时间在完整约束下协同调整；通过联合边界可行域检查局部结构候选是否能延拓为全局可行计划，必要时再解冻少量结构。

与 Calvo、TAPF-PC 的具体机制存在可检验差异，见第 2 节。但这仍是**待确认原创性与收益的研究候选**。固定部分整数变量、LP 重定时、Benders 分解、冲突诊断都已有研究；仅将它们组合不能直接认定创新。必须加入标准“局部整数自由＋全局连续重排”的同模型强基线。如果该基线已解释全部收益，应撤回独立算法创新主张。

## 2. 两项近邻工作：读到了什么、与方案具体差在哪里

### 2.1 Calvo 与 Capitán：结构保持的执行期修时

依据：[TRO 2025 论文 v3](https://arxiv.org/html/2411.02062v3)，重点 III、IV、VI-A、Algorithms 4–7、VII-E；另核对[作者仓库](https://github.com/multirobot-use/mrta_heuristic_planner)及 [`planRepair.m`](https://github.com/multirobot-use/mrta_heuristic_planner/blob/main/src/planRepair.m)。未安装/运行 Matlab 实现，当前 main 未固定 commit，不声称代码与论文逐行一致。

论文处理异构、电量、任务分片、同步与接力，已有连续监护应用。其公开模型不含跨任务前驱约束。在线修复保持任务分配，通过消耗等待时间、传播残余延迟和协调同步/接力恢复计划；新任务、失效或修复失败可进入重规划。

因此可复用其“先修时间”的思想；本方案要检验的是：**固定结构不能恢复时，能否只改变少量结构，并让外部时间联动，而非立刻重做所有剩余分配。**这不是宣称原框架无法扩展。

### 2.2 TAPF-PC：局部重新分配与路径修复

依据：[2026 预印本 v1](https://arxiv.org/html/2603.28968v1)，重点 §2、§4.2–4.5、§5.2、§6.2–6.3 与结论。模型是离散图上的目标访问、前驱及碰撞约束。方法已有多类邻域、后继闭包、边界补路/重定时、局部提案和 MAPF-PC 修复。不能概括成“外部时间全部不动”。

本方案拟比较的变化是：**以同一服务任务模型表达外部时间、能量和监护端点的联合延拓条件，而不把所有后继都释放为结构搜索变量。**原论文不是本项目在线服务修复的原生同题基线，适配必须单列。

原文 §5.2 尚写代码/实例将发布，本轮未核实到可运行作者包，状态为 `NOT_RUN / CODE_NOT_VERIFIED`。复现不能把自己实现的 MILP 邻域算法冒称作者原版。

### 2.3 不能遗漏的其他研究背景

[Hooker 的 Benders 研究](https://arxiv.org/abs/1910.11944)明确覆盖固定部分变量后简化的规划排程分解。因此下文采用的 LP 投影、可行性割和主从求解是借鉴工具，不列为本文新发明。增量时序推理、稳定计划修复和 fix-and-optimize 也必须继续查新。

本轮主要证据足以界定与两篇指定论文的差异；不足以证明全领域空白。

## 4. 精确定义研究问题

给定已执行历史、实时机器人状态、旧计划 `π0` 与更新后的任务/资源快照 `W+`，在统一在线预算内求一个可执行后续计划 `π`。

研究对象是**混合更新**：事件任务出现/关闭、服务位置改变、通道可用时刻改变、任务或行驶延迟、机器人不可用。原始分类证据的推断不在本章重做。

需要同时满足：

- 前驱、能力、取送绑定与相同机器人任务不重叠；
- 路径和服务阶段的共享资源预约；
- 电量与返回余量；
- 持续监护覆盖取送区间；
- 已执行事实、不可撤销动作及有效外部承诺；
- 明确区分的硬期限和软期限。

目标不是“修改任务越少越好”，而是：在相同硬约束下，获得更好的**首个可行计划时间—业务质量—计划扰动**关系。时间更改可能分布很广，结构更改应尽量有依据。

### 4.1 研究范围控制

第一版仅研究确定性滚动快照、有限任务、容量为 1 的资源、已给定的每条 arc 路径/耗时。沿用现有路径矩阵，不新增完整 MAPF 或学习控制器。服务点来自第二项，算法不能任意移动目标。

时间不确定性由执行反馈引发下一轮更新；不声称 STNU 动态可控性、机会约束或未知未来的保证。路径与预约层可行不等于连续动力学安全，后续执行仍需导航与保护机制。

双机固定角色 P0 用于排序/资源修复与系统验证。要验证“重新分配”的价值，应另设能力部分重叠的离线 benchmark，不静默更改 V3 角色，也不在硬编码角色场景中声称获得分配优势。

## 5. 统一模型：先把结构承诺与时间承诺分开

### 5.1 变量

| 类别 | 变量示意 | 修复时含义 |
|---|---|---|
| 离散结构 | `x_ij` 分配、`a_iuv` 机器人直接后继、`o_pq` 资源先后 | 仅选定的结构范围可改变 |
| 连续排程 | `s_j,f_j`、通道 enter/exit、等待、电量、充电量 | 未被不可撤销事实锁定时，可在全局约束下联动 |
| 持续监护 | `m_e_start,m_e_end` | 开始后 owner/start 是事实；未来 end 受交付完成和电量约束 |

普通服务任务保持 `f_j=s_j+d_j`。监护任务使用独立终点，例如：

```text
m_e_start <= s_pickup(e)
m_e_end   >= f_deliver(e)
m_e_end   >= m_e_start + d_min_monitor
s_next_of_monitor_robot >= m_e_end + travel_to_next
```

监护机器人在 `[m_start,m_end]` 内持续占位。若计入时间相关监护能耗：

```text
E_monitor_end = E_monitor_start - rho_monitor * (m_end - m_start)
E_monitor_end >= E_safe + required_return_energy
```

`rho_monitor` 是待校准的研究能耗参数，所有方法相同；不能给候选法忽略等待/监护耗电而给基线计费。没有标定前先报告相同简化模型结果与敏感性，不能称真实续航保证。

事件明确关闭时，由上游提供合法关闭时刻与待取消任务；单轮优化不允许自行选择“事件关闭”来逃避监护约束。未完成且位置失效时，沿用上游暂停/安全规则。

### 5.2 承诺的四类处理

1. **历史事实**：已完成动作、实际开始时刻和已经消耗的电量不可改写。
2. **执行中不可中断的属性**：例如监护 owner 与已开始时刻固定，结束尚未来临则不能机械固定为旧预测值。
3. **不可撤销的近期预约**：按共同外部协议作为硬约束；若新环境已使其不安全，先执行安全中止流程，不通过优化器放松安全约束。
4. **可修订未来安排**：分配、先后、计划时刻可按代价修改；时间改变与结构改变分别记录。

每台机器人保留自己的可用时刻/状态。R1 已进入监护，不应因此将空闲 R2 的新任务也推迟到旧 monitor finish。

### 5.3 共同目标

建议沿用项目加权目标并显式补齐变化项：

`J = C_business + mu * D_plan`。

业务成本含响应/软期限延误、路程、等待、能量；变化代价区分重新分配、机器人/资源先后变化、开始/结束偏移和可撤销预约变化。权重与归一化在 validation 冻结，全部方法相同，并报告各分量与权重敏感性。

硬 deadline 直接入约束；软 deadline 才用 tardiness。约束违例不靠目标惩罚“抵消”。本轮不确定具体新权重，不修改现有配置。

释放一个变量不等于最终改变该变量；搜索范围大小与实际计划变化分别统计。新任务的必要插入/合法取消也与可避免的旧任务变化分开。

## 6. 改进机制：外部联合可行域，替代整块冻结或整块解冻

### 6.1 两个不同的修复范围

定义结构自由范围 `F`，由可重分配/重排任务集合与可改变的资源顺序对组成。任务身份和路径端点的变化按当前快照更新。

- `F` 内可调整相关离散结构。
- 外部保持原 owner、外部任务相对次序、有效路径及资源相对次序；其未来时间/电量可以联动。
- 允许核心任务插入外部序列时，只固定外部任务之间的相对次序，不能同时固定所有旧直接后继 arc。新连接的 travel 与资源占用必须重算。

因此本方法的“局部”专指离散结构搜索范围，不声称完全不访问外部任务，也不保证时间改变任务数最小。

### 6.2 联合边界接口

将核心候选决定与共享连续边界变量记为 `v`。它至少包含跨边界前驱/后继时刻、资源 enter/exit、监护结束和机器人连接点电量。

固定外部结构 `sigma_out` 后，外部连续可行延拓集合定义为：

`P_F = { v | 存在外部时间/能量变量 z，使全部外部及跨边界约束成立 }`。

**必须保存联合关系。**例如两个接口时刻各自都允许在某一区间内选择，并不意味着任意组合都满足通道先后或监护覆盖。将 `P_F` 替换为逐变量独立窗口，只能视为放松或近似，不能据此发布计划。

所有候选跨边界 arc、潜在共享资源使用、监护联系和返回电量都必须进入接口，不能只考虑旧计划中实际使用的边。若接口几乎覆盖全部问题，应记录退化而非仍声称局部加速。

### 6.3 算法主从结构

主问题选择 `F` 内分配、排序和资源顺序，提出连续边界 `v`；外部检验器固定这些选择，求全局剩余连续排程 LP，包括时移/软延误等成本。

可行时取完整延拓计划并验证。不可行时反馈**对当前外部结构有效的联合边界限制**，让主问题改变局部候选，而非立刻释放全部后继。

为了让这一描述可实现，标准形式可写为：

```text
外部 LP：  phi(v) = min c^T z
           subject to A z >= d - D v
```

`z` 的上下界和等式转换均包含在约束内。若得到 `lambda>=0, A^T lambda=0` 且 `lambda^T(d-Dv)>0`，可添加：

`lambda^T(d-Dv) <= 0`。

这只是标准 Farkas 可行性割。若目标也分解，需要合法 LP 对偶 `pi>=0, A^T pi=c`，并给主问题增加：

`theta >= pi^T(d-Dv)`。

`theta` 须有有效下界，主问题成本和外部成本只能计一次。仅加可行性割不能据此宣称得到同模型最优解。上述对偶表达依赖标准形式与自由变量处理正确，未来需用小实例独立核对。

同一轮应使用所有候选行组成的统一线性编码，使 `A` 固定、选择项进入右端；若候选结构改变 `A`，则割必须带适用条件或只在该结构下使用。外部结构、服务点、任务、路径或 world revision 变化后，旧割必须失效/重建，禁止跨模型复用未经证明的割。

### 6.4 什么时候扩大结构范围

一次 LP 候选失败只说明该候选不可延拓，不说明当前 `F` 必须扩大。先加有效割，继续尝试核心内的其他选择。

只有主问题在有效割下证实当前范围无解，才能说“保持这些外部结构无法恢复”；到时根据约束来源，优先释放相关资源先后、连接顺序或任务 owner。冲突来源用于**启发式选择**，不冒称最小冲突集或最小修复集合。必要时系统性扩大到全部可撤销结构。

超时必须标 `UNKNOWN/BUDGET_EXHAUSTED`，不能当作无解证明。预算驱动的扩张另记为 heuristic expansion。无 LP ray 接口时可采用已求最优的 phase-I LP 及可验证对偶，或先用同范围单体 MILP 验证；不能把普通 slack 打分当有效割。

### 6.5 完整流程伪代码

```text
输入：实际状态、有效执行承诺、旧计划、W+、统一总预算 B
1. 固定历史，建立每台机器人独立的可用状态；核查硬安全前提。
2. 固定全部未来离散结构，先求一次全局连续重定时 LP。
3. 若可行：保留该计划作为可发布 incumbent；按剩余预算决定是否继续优化。
4. 若不可行/需优化：从直接失效结构建立小范围 F。
5. 在 F 内主问题提案 ↔ 外部 LP 延拓之间迭代：
      可行：更新完整 incumbent；不可行：加入适用的有效割。
6. 当前 F 已证无解，或按已记录的预算策略：扩大少量结构并重建接口。
7. 必要时释放所有可撤销结构，进入同目标 Full-Replan。
8. 统一 validator 通过、world revision 未过期，且发布时的可用时刻/目标仍有效，才可发布。
9. 无合格新计划：仍有效的旧计划按共同协议执行；失效部分安全停等。
```

总预算包括传播、LP、建模、主问题、割、扩大范围、校验与回退。可先固定一个小比例用于初始 LP，剩余预算自适应分配；具体比例用先导调优，不能给每次局部求解各用完整 B。首个可行计划与截止时最佳计划分别评价。

## 7. 一个可手算的辨别案例

以下是**拟用于单元级方法验证的解析实例**，不是已做实验。单位为秒，旧计划在更新前可行；外部输入只改变交付最早完成时刻，所有方法收到相同信息。

两机器人：R1 正在监护，R2 交付后还有常规任务。旧交付结束 `d=80`、monitor end `m=80`。R1 下一任务 U 开始 `u=90`，到 U 需 5 秒且穿越 H，预约为 `[u-5,u]`。R2 后续穿越 H 的进入时刻 `v=92`，占用 `[v,v+5]`，交付后到 H 至少 5 秒。

旧资源次序为 R1 在前，安全 buffer=1。U 时长 10、完成 deadline=120，即 `u<=110`；R2 后续安排要求 `v<=105`。

更新后交付最早结束 `d=90`，相应约束：

```text
m >= d
u >= m + 5
v >= d + 5
v >= u + 1       # 保留原通道次序
u <= 110
v <= 105
```

取 `m=90,u=95,v=96` 即可行。无需改变 owner 或资源顺序，但 monitor、U、后续通道预约都需时间更新。此例只证明需要把两类修改区分；**充分适配的时间修复也可能解出，不能据此宣称优于 Calvo**。

消去 `m` 后，两个接口的联合约束包含 `v>=u+1`。即使取精确边际范围 `u∈[95,104]`、`v∈[96,105]`，组合 `(u=104,v=96)` 仍不可行。它用于检验联合接口与独立窗口的差别。

再设一类预注册变体，R2 的近期可用预约固定为 `v=95`（尚未执行且允许改变两次预约的先后）：保留原次序要求 `u<=94`，与 `u>=95` 冲突。仅解冻该资源顺序后改为 R2 先过 H：`u-5>=v+5+1`，可取 `u=106,m=90,v=95`。这时无需改任何 owner，但需要一次结构变化。

反向对照：若同类变体还要求 `u<=100`，两种资源顺序均不可行，应报告不可行或采用模型中实际存在的其他方案，不能靠放宽安全 buffer 获胜。固定 `d` 较小、资源充足时也应包含无需结构修复的情况。

正式仿真还需验证路径时长、空间占位、所有其他任务及电量；上述局部算式不替代完整模型可行性证明。

## 8. 实质区别与可主张的性质

| 对照对象 | 本方案真正改变的对象 | 不能声称的差异 |
|---|---|---|
| Calvo 的延迟修时 | 从保持旧结构扩展为小范围结构调整，并在完整服务约束下检验外部连续延拓 | 不能声称首次连续监护、跨机传播或先修复后重规划 |
| TAPF-PC 邻域方法 | 对当前服务排程问题，保留外部结构并表达联合连续边界，避免将所有时间后继都作为自由结构 | 不能声称其没有边界补路/重定时，也不能冒充完整 MAPF 的增强版 |
| 项目当前 LocalRepair | 分开冻结属性；开放外部时间；加入完整接口；避免一开始将时序闭包整体自由化 | 代码修错、统一两套实现不单列算法创新 |
| 标准 masked MILP＋全局重定时 | 可行域应相同；区别应来自有效边界割、子问题复用与结构范围选择的求解效率 | 不能凭换名或使用 Benders 宣称原创 |

可尝试证明的性质：

1. **固定范围延拓等价性。**若接口完整、编码线性且分解精确，主问题满足 `P_F` 等价于对应固定外部结构的单体模型存在连续延拓。
2. **拼接可行性。**在相同快照、所有跨边界约束保留且完整 validator 通过的条件下，核心与外部构成同一离散任务模型的可行计划。
3. **有限结构扩张。**每次严格释放至少一项有限可撤销结构时，扩张次数有限；不等于给定秒级预算内必然完成。

这些是拟证明的条件性质，不是已获定理。Benders 的一般正确性来自已有方法，不算新的理论结果。若想主张新理论，应进一步给出本任务结构特有的接口充分性或有效缩减性质，不能复述通用分解定理。

`F` 越小可行域越受限；全量精确最优值不大于局部范围精确最优值。因此研究目标是有限预算表现与计划稳定性，不是击败同模型已求得的全局最优解。

## 9. 实验协议：三层比较，排除模型与求解器混淆

### 9.1 原生复现层

- Calvo：在作者原生模型下复查延迟修复/回退，记录 commit、Matlab/求解器、输入和结果。选共同支持的子问题比较；不把新前驱/通道约束强加给原版再判失败。
- TAPF-PC：先核实代码可用性；若不可得，按公开算法重实现须标 `reimplemented` 并用小实例核验。原生目标访问 benchmark 与本项目服务 benchmark 分表。
- 原文性能百分比不与本项目数字横比。两项均 `NOT_RUN`，本轮无复现成绩。

### 9.2 同模型核心算法层

第一批应先做以下对照，全部使用相同任务、监护、电量、期限、执行前缀、路径及目标：

| 编号 | 方法 | 隔离的问题 |
|---|---|---|
| B0 | Full-Replan，不设变化惩罚 | 保留历史参照，不作为主要胜负依据 |
| B1 | Full-Replan＋同变化惩罚、同 warm start | 排除目标不公平；小规模足预算作最优参照 |
| B1r | 相同初始重定时 LP＋B1 | 排除首个可行解优势只来自新法先做了 LP；两阶段均计入相同总预算 |
| B2 | Calvo-inspired 时间传播＋共同全局约束验证，失败进入 B1 | 仅修时间是否足够；明确为适配版 |
| B3 | 所有结构固定＋最优全局重定时 LP | 排除收益只是时间传播实现太弱 |
| B4 | 当前闭包式 LocalRepair 在统一模型上的版本 | 比较原项目方法；旧原版结果另保留 |
| B5 | 前驱/冲突/低松弛量 LNS/ALNS＋共同 MILP 内核 | 对照成熟邻域思想，标 TAPF-inspired，非作者原版 |
| B6 | 小范围自由整数＋全局连续变量的单体 MILP | 与候选法同范围、同可行域、同目标，检验分解是否真有价值 |
| P | 本方案的联合接口分解与结构扩张 | 综合候选 |

B6 必须保留，是最接近数学等价的强对照。比较 P 与 B6 时先固定相同范围序列，隔离分解；比较范围策略时统一内核，隔离邻域选择。否则“模型更灵活”“选范围更好”和“分解更快”无法区分。

warm start 可能因扰动而失效，须记录是否被求解器接受。候选法产生的可行初始计划不能无成本独占；以共同初始化或明确计入各自初始化时间的方式比较，不给任一方法未来真值。

### 9.3 消融

- 同范围、同目标，联合接口换成独立时间窗口，最终仍做完整 LP/validator 检查：测量被误判为可接纳的候选与浪费时间，绝不将冲突计划作为有效结果。
- 保留完整接口，去掉约束反馈，仅排除当前失败候选：检查有信息的割是否减少重复失败。
- 保留分解，结构范围按固定闭包、随机等规模、低松弛量、冲突来源扩张：检查范围选择增益。
- 保留范围策略与完整约束，用 B6 替代分解：检查主从开销是否值得。
- 不得通过删除监护/资源/电量约束来给“消融”增加不公平可行域；另设确无这些需求的场景测试适用边界。

## 10. 场景、指标与否定条件

### 10.1 场景因子

| 条件 | 要检验的机制 |
|---|---|
| 无扰动/延迟被等待完全吸收 | 是否有不必要结构修改和额外开销 |
| 大时序传播、小结构必要变化 | 候选最应有价值的区域；不能只做这一类 |
| 监护终点随交付变化且影响后续资源 | 是否保留联动端点、电量与边界关系 |
| 需要改变通道先后或重新分配 | 是否适时释放结构而非无限修时 |
| 新任务/服务位置变更 | 不限于纯延迟；新边界 arc 是否完整 |
| 密集全局扰动/高资源耦合 | 接口或范围退化时能否合理回退 |
| 全局不可行 | 是否正确诊断而非发布冲突/过期计划 |

离线规模建议先 `2/4/6` 机器人、`10/20/40` 任务；先导再决定更大规模。主因子包括前驱密度、共享资源利用率、期限松弛、监护负荷、能力重叠和扰动幅度。两/三类地图拓扑交叉测试，不能只用一个走廊或只用对称任务。

额外诊断可用离线精确分析估计“保持原结构是否可修复”“最少需要哪些结构变化”；这些 oracle 标签仅用于评估分层，不能提供给在线算法。

### 10.2 主要指标

预注册主指标为相同总预算下的**全约束可行恢复率**与**首个可行计划时间**；截止时的 `J` 和各分量作为质量指标。不能仅报告少改任务。

同时报告：结构变化数、时间偏移、监护中断/期限/资源违例、任务完成与响应、自由整数变量数、接口大小、LP/主问题调用次数、范围扩张、回退率及全过程 p50/p95。时间改变任务数即使增加，也必须如实展示。

先离线快照比较，再做相同外生扰动流的闭环任务仿真。离线候选使用完全相同输入；闭环分叉后不声称观察轨迹逐帧相同。2/5/10 秒可作初始研究预算扫描，不改变 V3 冻结门限；正式预算先导后固定。

以独立 run 为统计单位，使用配对实例与 solver seed，报告绝对成功/失败数、配对差与 95% CI。先导后确定样本量，30 个 seed 不是统计保证。失败、超时、模型不可行、过期结果都入分母并分原因；成本既报告全样本规则，也报告共同成功子集，后者不独立代表整体优劣。

### 10.3 明确的否定条件

以下任一结果都会迫使收缩主张：

1. B3 已恢复绝大多数情况，新增结构算法无实际必要。
2. B1 在同预算、同目标下同样快且质量更好，局部修复优势不成立。
3. P 只超过当前代码，不能超过 B5/B6；收益来自更强模型或修复缺陷。
4. 联合接口并未减少失败候选，或 LP/割开销抵消所有收益。
5. 新法仅在小范围有利样例有效，接口稠密后普遍失效且回退代价高。
6. 改动更少只因牺牲响应、延长监护耗电、漏计跨边界冲突或忽略失败。

相反，若 P 与 B6 数学等价且在预算内稳定更快，这支持求解算法贡献；若只有 B6 比当前原型好，则先按冻结语义改进/工程优化表述，不能把数学等价建模包装成新理论。

## 11. 先做哪些研究交付，再决定是否实现

1. **模型卡**：冻结监护端点、硬/软 deadline、外部相对次序与边界 arc 的含义；所有基线共享。先手查第 7 节实例与一个全局不可行反例。
2. **近邻差异卡**：以 Calvo VI-A、TAPF-PC §4.2–4.5、通用重排/分解工作继续查新；补充是否已有等价“局部结构＋全局连续修复”。如已存在，调整方法而非换名。
3. **最小数学门槛**：在小实例中证明/核验 `P_F` 与 B6 的可行域及最优值一致。若接口遗漏约束，先修模型，暂不做规模实验。
4. **最小算法先导**：先比较 B1/B3/B4/B6，再加 B5 与 P。只有分层价值和分解收益均有迹象，再接 ROS 在线修复；当前不进入实现。

**现阶段可用创新候选表述：**

> 针对事件响应中连续监护、取送与共享资源造成的跨任务时序传播，研究时序影响范围与结构修复范围分离的增量协同排程方法；通过联合边界可行域协调局部结构优化与外部时间/能量延拓，并依据不可延拓证据扩大结构范围，在统一约束和预算下验证其可行恢复效率与计划扰动。

这句话是研究计划，不是成果声明。若不能超过数学等价的单体模型及成熟邻域基线，应撤回算法先进性主张。
