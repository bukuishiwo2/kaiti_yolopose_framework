# Clinic实验工程审查：重复实现与前置检查缺口

日期：2026-11-17。范围：只审查现有实现与实验记录，新增本文；不改代码、不启动仿真、不删除历史结果，不修改已验收文件或清单。

## 判断与责任

用户对基础配置错误和实验成本的批评成立。此前未先统一实验入口、建立分层预检，就反复进入完整闭环；多个本可在静态检查或短探针中发现的问题进入长时间运行。逐个修复并最终完成任务不能抵消这部分可避免的成本。这是实验组织和工程实施的不足，不应归因于“机器人系统复杂”而淡化。

历史a1–a12包含24个不同版本下的失败、诊断和主动停止运行，不能全部称为同类配置错误，也不能以跨版本成功率解释。各轮原始状态已保留。

## 哪些是复用，哪些存在重复和技术债

| 部分 | 当前判断 | 后续处理原则（本次不实施） |
|---|---|---|
| Clinic世界、TB4模型、Nav2规划控制、标准清图服务、现成NormalBed、CBC | 已复用既有组件，没有重新实现这些基础算法 | 保持复用；不能列为自研算法贡献 |
| 事件任务协议、MILP承诺投影、失效检测、任务级修复范围、独立计划检查 | 对本研究有明确用途 | 保留最小接口，避免把基础适配包装成创新 |
| 导航/恢复调度的自写状态机 | 与Nav2已有导航、恢复职责有重叠；任务启动和资源ACK仍需任务层处理 | 对照已安装组件逐项评估复用边界；无需另造避障器，不能未经验证声称整段可直接替换 |
| run_bed_episode → recovery → static_delta叠加入口与导入时类替换 | 为连续修补形成多个现行实现层，维护成本过高 | 历史冻结副本留作复现，后续开发收敛到单一明确入口；保留历史不要求持续叠加补丁 |
| 多个单用途探针与启动脚本 | 探针本身有价值，但参数、环境与启动逻辑分散 | 共用配置与启动器，探针按场景参数组织，不再为相似故障添加一个完整入口 |
| source.replace/exec拼接审计、渲染与AST抽取测试 | 实现耦合且脆弱，单方法回归不等于集成链路通过 | 后续以显式函数/接口复用；离线状态测试不能替代真实topic/TF/服务链检查 |

核查依据：`/home/yhc/clinic_planning_ws/tools/run_bed_episode.py`、`run_bed_episode_recovery.py`、`run_bed_episode_static_delta.py`、`audit_bed_episode.py`、`render_bed_episode.py`及本轮change_manifest。以上为工程审查，不声称已完成收敛。

## 进入长实验前本应完成的检查

| 问题 | 应提前采取的检查 | 本轮缺口 |
|---|---|---|
| costmap使用错误的scan命名空间 | 核对最终解析的参数/重映射、真实端点及QoS；确认每台机原始scan到local/global costmap的真实更新 | 早期仅有激光发布、静态导航通过，没有验证完整消费链 |
| TF/时钟/导航与恢复服务 | 校验每个命名空间frame链、时间源/新鲜度、生命周期、动作和服务存在且一次调用成功 | 未形成统一的启动门槛，检查散落在不同入口 |
| 静态边界被计作新增障碍、移除后残留 | 先录空场基线，再做一次置入/移除短探针，核对scan、两层图及恢复判据 | 检测口径未经完整短链路验证就进入长闭环 |
| 清空位长期驻留阻塞后继任务 | 带其他机器人实际驻留的路径查询，外加服务—清空—依赖的短交互探针 | 仅凭单条路径可达不足以证明多机布置可执行 |
| CBC种子边界值与无初解分支 | 用实际导出格式回放种子；检查容差、完整矩阵、种子无解/未知/全问题无解的区分 | 一些数值和退出分支到在线求解时才暴露 |
| 跨节点ACK时间、当前状态与历史事件混用 | 审计器先对已知事件序列、同tick/跨tick记录做验证，时间容差逐边检查 | 首次完整后处理才发现链式容差和历史标志问题 |

多机器人动态交互缺陷需要集成测试；应通过最短复现探针发现和定位，而不是把完整医院闭环当作基础调试工具。

## 后续工作门槛

1. **静态预检**：读取唯一配置源，核对最终话题、frame、端点、资源点、预算和模型语义。未过不启动完整世界。
2. **最小集成冒烟**：真实一台机器人完成一次到达/服务/清空，确认生命周期、数据消费、ACK与超时链。
3. **专项短探针**：真实障碍出现—移除—恢复，三机共享点占用—驶离—依赖释放。只运行本次变更涉及的探针。
4. **正式运行**：预检通过的同一源/配置哈希进入实验；不得预检一个版本、统计另一个版本。先单策略验收，再安排对照批次。
5. **成本控制**：首个异常立即保存最小证据并停止无效长跑；定位根因后只重跑受影响检查。优先提取日志摘要，避免反复全量输出与轮询叙述。

这是一份待实施的流程要求，当前尚无把上述检查统一执行并阻断启动的完整预检入口。已有独立检查不等于已经具备这套门禁。

## 下一步与变更范围

后续恢复编码时，优先收敛唯一实验入口和最小预检，再开展新增算法对照。现有源/原始数据冻结保留；不为清理技术债重新执行全部旧实验。当前仅新增本文，无代码、配置或运行变更。
