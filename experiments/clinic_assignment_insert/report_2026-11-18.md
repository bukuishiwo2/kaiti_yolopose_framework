## 3. 冻结契约、方法与生成规则

完整数学和时间说明见同目录README。冻结目标未新增任何项或权重：

`J = 4*阶段响应 + 0.1*(Cmax-now) + 0.1*常态释放等待 + 2*accepted换机数 + 0.05*accepted绝对开始时移 + 0.1*phase旅行`。

核验响应从candidate_at到verify服务开始；监护响应从confirmed_at到monitor开始；交付从confirmed_at到deliver完成，另列candidate端到端值。任务release及360秒开始期限在生成时固定，重复规划不移动。常态等待不是逾期惩罚；仅routine_window条件有显式额外硬截止。accepted成本只对真实已接受的未派发后缀计一次，不把首次名义分工偏离冒充accepted改派。

所有方法使用相同能力、模型空间域、依赖、货物同车关系、监护覆盖、资源entry/service/clear和不可撤销前缀。5秒算法墙钟预算包含构造、建模、求解和验证；CBC seed17、单线程、单CPU、BLAS线程1，方法执行顺序轮转。首可用解为经过验证的初解时间，CBC内部首次整数解时间另列，不混用。

| 方法 | 第三角色政策T | 常态归属域O |
|---|---|---|
| B0 固定分工重排 | 保留 | 全部保持真实accepted owner，应急固定原r1/r2角色；可重排时间与顺序 |
| B1 最早服务任务束贪心 | 保留 | 固定常态accepted owner及顺序，枚举合法任务束插入位置；失败不回退MILP |
| F00 | 放宽，仅反事实 | 仅necessary_normal可换机 |
| F01 | 放宽，仅反事实 | 全部合法未派发常态可换机 |
| F10（本轮B2） | 保留 | 仅necessary_normal可换机 |
| F11（本轮合法B3） | 保留 | 全部合法未派发常态可换机 |

necessary_normal固定为C0_r3_W2；第三角色政策要求它与monitor和courier不同owner。执行器存在硬提交检查，T=OFF永远标记`OFFLINE_POLICY_RELAXATION_ONLY`。四个F共享同一个problem及SHA；仅policy_owner和policy_third行改变。移除两类政策行后数学模型、变量和目标签名一致；专项测试验证T只增3行、O只减少owner锁。

每个历史来源预先固定5个response条件：observed、r1额外不可中断hold160秒、G1额外预约240秒、C0_r3_W3硬截止max(now+240,accepted_finish+90)、原A应急角色限域。后四者是明确标注的反事实，未冒充真实历史扰动。两来源共10条件×6方法=60调用；另2个verify条件×4合法方法=8调用；4个reference-erased输入×2方法=8调用，总16输入76调用。生成规则在求解前冻结，无按结果筛选。

## 8. 是否需要新机制

当前发现的是**任务束与已接受常态后缀联合协调的条件性决策价值**，不是联合优化的可行性必要性：B0/B1/受限MILP均可行。联合模型在部分代价降低的同时牺牲交付和改派稳定性，且现有联合MILP已可得到这些方案。

因此本轮没有新增候选域筛选、权重、目标项或求解器机制。只有4项常态后缀，依赖/共享资源筛选很可能仍扩到全部4项；目前不能支持“减少搜索规模”的新算法贡献。扩大可行域本身不作为创新。

下一阶段先冻结更大真实accepted后缀的输入规则及业务可接受交付边界，比较现有贪心/受限/联合方法的决策和计算缺口，再决定是否开发任务束和资源竞争驱动的必要后缀筛选。两段相关历史运行、固定seed、模型旅行代价和未资格并发均限制外推；不得声称泛化性能、真实执行成功率或学术创新已成立。
